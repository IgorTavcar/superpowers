Page 01 · The big idea

The Essence

Superpowers didn't begin as a product. It began as one developer's private toolkit for steering his "agentic buddy" — a set of hard-won procedures he'd been quietly systematizing until Anthropic shipped a way to share them. At its heart is a single, almost contrarian bet: that what coding agents lack isn't capability, it's discipline — and that discipline can be written down as plain Markdown and handed to any model.

What Superpowers actually is

Strip away the name and the lore, and the project describes itself with disarming plainness. It is not a model, not an agent, and not a pile of clever prompts. It is a methodology — a complete way of working — packaged so that an agent will actually follow it.

"Superpowers is a complete software development methodology for your coding agents, built on top of a set of composable skills and some initial instructions that make sure your agent uses them."README, obra/superpowers

Two halves do all the work. The first is a library of skills: small, version-controlled procedures — one folder, one SKILL.md each — that encode an expert workflow as natural language a model can read and execute. The second is the "initial instructions" — a session-start bootstrap whose entire job is to make the agent reach for those skills at the right moment, unprompted. Skills alone are inert; the bootstrap is what turns a directory of Markdown into a program library the agent runs.

★

The crucial framing. Skills are not documentation about the agent. As the repo's CLAUDE.md puts it, "Skills are not prose — they are code that shapes agent behavior." The whole project is meta-programming: procedures kept under git, indexed by metadata, and composed at runtime into a development process.

The payoff, in one line: Superpowers doesn't try to make the model smarter. It makes the model disciplined. A capable model that skips the steps still ships sloppy work; this is an attempt to stop it from skipping the steps.

Origin story

Superpowers is, in the most literal sense, a personal-workflow project that escaped the lab.

Its author is Jesse Vincent — a longtime open-source developer (creator of RT/Request Tracker and the Keyboardio), who writes at blog.fsck.com under the wonderful banner "Massively Parallel Procrastination" and goes by the handle obra on GitHub. For weeks before there was anything to release, he'd been refining a private system for getting more reliable work out of Claude Code. Then, on a single October morning in 2025, Anthropic handed him a delivery vehicle.

"I've spent the past couple of weeks working on a set of tools to better extract and systematize my processes and to help better steer my agentic buddy. I'd been planning to start to document the system this weekend, but then this morning, Anthropic went and rolled out a plugin system for claude code."Jesse Vincent · "Superpowers" · Oct 9, 2025

The plugin launch is the spark, but the workflow itself was older. Vincent had already written up a brainstorm → plan → implement process in his earlier "How I'm using coding agents" posts. Superpowers' real innovation was making that process trigger itself — no command to remember, no prompt to paste. He also didn't start from a blank page: he reverse-engineered Anthropic's earliest MS Office skills to build the core skill system, and drew inspiration from Microsoft's Amplifier (Sam Schillace, Brian Krabach), which "uses this same pattern of a coding agent that improves itself by writing out markdown docs and writing tools for itself."

The core belief: discipline, not capability

If there is one sentence that captures the soul of the project, it is the wager about where the problem really lives.

It's the bet that what AI coding agents lack isn't capability — it's discipline. And that discipline can be distributed as plain Markdown.

The reasoning is almost embarrassingly practical. A strong model already knows how to write a test, isolate a branch, or chase a bug to its root cause. What it doesn't reliably do is choose to — especially under pressure, when a shortcut looks tempting and "just this once" sounds reasonable. So Superpowers spends its effort not on raw intelligence but on compliance: getting a smart, occasionally-rationalizing interpreter to follow a good procedure even when it would rather wing it.

That's why the discipline-bearing skills read less like tutorials and more like contracts. They carry an Iron Law, a table of common rationalizations paired with their rebuttals, and a foundational cut designed to close the largest class of loopholes at once:

"Violating the letter of the rules is violating the spirit of the rules."test-driven-development/SKILL.md
✓

Why it can travel as text. Because the unit of value is a procedure, not a weight, a skill is just a file. It can be committed, diffed, reviewed, copied between projects, and improved over time — the same lifecycle you already use for code, now applied to how the agent thinks.

Skills give your agents Superpowers

The name isn't decoration. For Vincent, a skill is a genuinely potent thing — and he's refreshingly honest about why it works.

"Skills are incredibly powerful. They're magic words that make your agent behave differently, even without you asking directly… They're not just subject to prompt injection — They are the very definition of prompt injection."Jesse Vincent · "Skills for Claude!" · Oct 16, 2025

That candor matters. The same mechanism that lets a malicious string hijack an agent is the mechanism Superpowers uses, deliberately and in the open, to install good habits. A skill is a curated piece of context that reshapes behavior the moment it's read — so the discipline of the corpus is the whole safety story. The framework treats its own instructions as load-bearing and adversarially tested, precisely because text this powerful must be trustworthy.

There's also a subtle design insight buried in how skills are surfaced. Each skill's description describes only when to use it — a trigger predicate, never a summary of what it does. The reason is empirical:

"In my testing, I've found that showing only 'When should Claude use this skill?' leads to better compliance. When Claude thinks it knows what a skill does, it's more likely to believe it's using the skill and just wing it, even if it hasn't read it yet."Jesse Vincent · "Skills for Claude!" · Oct 16, 2025

Tell the agent the gist, and it will confidently improvise the rest. Tell it only "this applies now," and it will actually open the file and follow the steps. The framework is built around that one stubborn fact about how models behave.

Brainstorm → Plan → Implement

The methodology Superpowers encodes isn't new to Vincent — it's the process he'd already documented. The breakthrough was deleting the friction: you no longer invoke it. It invokes itself.

"If Claude thinks you're trying to start a project or task, it should default into talking through a plan with you before it starts down the path of implementation."Jesse Vincent · "Superpowers" · Oct 9, 2025

So when you say something as casual as "let's make a react todo list," a Superpowers-equipped agent doesn't sprint to the keyboard. It steps back, interrogates intent, and turns the conversation into a spec — then a plan detailed enough, in Vincent's memorable phrasing, for "an enthusiastic junior engineer with poor taste, no judgement, no project context, and an aversion to testing to follow." Only then does code appear, written test-first.

★

The acceptance test. The repo's own definition of a working install is behavioral: that exact "react todo list" prompt must auto-trigger the brainstorming skill. If it doesn't, the bootstrap never loaded and, in the repo's words, "the skills are dead weight — present on disk but never invoked."

Self-improving skills

The cleverest move in the whole design is recursive: among the very first skills Vincent taught the system was the skill of making skills.

"One of the first skills I taught Superpowers was How to create skills."Jesse Vincent · "Superpowers" · Oct 9, 2025

Once an agent can author and refine its own procedures, learning becomes a workflow rather than a wish. The foundational move is almost startlingly simple:

"You can hand a model a book or a document or a codebase and say 'Read this. Think about it. Write down the new stuff you learned.' … it is insanely powerful."Jesse Vincent · "Superpowers" · Oct 9, 2025

For Vincent this is the most interesting frontier of all — "getting the LLM to create its own skills… is the key to a whole bunch of avenues for agentic self-improvement." And the meta-skill isn't a free-for-all: authoring a skill is itself governed by test-driven development. The rule, stated flatly in writing-skills, is that "Writing skills IS Test-Driven Development applied to process documentation" — new procedures are pressure-tested on fresh subagents, in deliberately adversarial scenarios, until they hold up. The program that writes programs is held to the same standard as everything it produces.

✓

Tested like code. A skill isn't "done" when it reads well. It's done when a fresh agent, dropped into a high-pressure scenario, picks the right action and cites the skill it followed. Drawing on persuasion research, the repo notes, hardened instructions "more than doubled compliance rates (33% → 72%)."

What it is, in four parts

When Vincent breaks the project down himself, it resolves into four cleanly separable layers — a useful map before you dive into the architecture.

① The bootstrap

"A bootstrap that teaches Claude Code to load SKILL.md files and when to use them." Loaded at session start, it's the control layer that makes everything else auto-trigger.

② Skills for managing skills

"A set of SKILL.md files designed to create, manage, and share SKILL.md files." The self-referential core — meta-programming made concrete.

③ The Architect / Implementer method

Skills that "encode my Architect/Implementer agentic coding methodology, starting from the brainstorming process and running all the way through the TDD process."

④ Other engineering skills

"A set of SKILL.md files that encode a bunch of other software engineering skills." The grab-bag of everyday competencies that round out the library.

Breakdown paraphrased and quoted from Jesse Vincent, "Skills for Claude!" (Oct 16, 2025).

From idea to system

Those four layers are the bridge from philosophy to structure. The belief — discipline over capability — needs a control layer to enforce it, a way to grow and curate the procedures, a concrete method to encode, and a body of skills to populate it. The mantra: "Why am I doing this?"

If the project has a beating heart, it's a question — one Vincent surfaced months later while building his favorite new feature.

By Superpowers 5 (March 2026), the framework had grown a feature called Visual Brainstorming: instead of sketching designs as crude ASCII art, the agent now renders them as real HTML mockups in a local browser. It grew out of a recurring frustration — and led Vincent straight to the idea that, for him, sits above all the tooling.

"It took me far too long to remember what might be the most important mantra of agentic coding: 'Why am I doing this?'"Jesse Vincent · "Superpowers 5" · Mar 9, 2026

It's a fitting capstone, because the whole framework is that question made operational. Brainstorming-before-code asks it. The adversarial spec-review loop — which hunts down "TBD" and "fill this in later" placeholders before they become bugs — asks it. Test-first development asks it. Every gate Superpowers installs is a structured way of forcing the agent (and you) to keep answering it instead of charging ahead.
