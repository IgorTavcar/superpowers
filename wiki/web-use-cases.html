Page 08 · The reception

From the Web

Superpowers landed in October 2025 and almost immediately split the room. Experienced engineers wrote rave reviews; Hacker News sharpened its knives; and at scale the project surfaced an uncomfortable truth about agentic contribution. This page is the honest, sourced version — praise and skepticism, side by side, with a real URL behind nearly every claim.

A divided, mostly-positive reception

Among practitioners who actually ship code with coding agents, the verdict skews strongly positive. But the response is genuinely mixed — and the headline numbers you'll see quoted around the web do not agree with each other.

The pattern is consistent across sources: people who use Superpowers on real, multi-file work tend to love it, while people reacting to the idea of it — a Markdown framework that imposes "discipline" on a model — are more divided. The framework doesn't claim to make the model smarter; it claims to make it follow a process. Whether that's worth the ceremony depends entirely on what you're building.

!

The raves

The strongest endorsements come from independent developers with no affiliation to the project — people describing concrete wins on their own codebases.

"Using Claude Code with Superpowers is so much more productive and the features it builds are so much more correct than with stock Claude Code."Evan Schwartz — "A Rave Review of Superpowers (for Claude Code)"

Schwartz's writeup walks the flow: brainstorming explores the codebase, presents multiple options with tradeoffs, sketches a roughly dozen-bullet plan, then writes an editable Markdown design doc you can comment on in your own editor. His favorite part is being able to weigh in on a concise outline rather than rewriting a multi-page default Plan-mode document.

Richard Porter reports the same reliability on large features. His plans break into 12–15 tasks of about 2–5 minutes each; before Superpowers he'd "describe the feature, hope Claude understood... watch it write code for 10 minutes, then spend an hour fixing the inconsistencies." After, features spanning 15+ files execute consistently with fewer regressions — because, as he puts it, "each subagent starts fresh with only the context it needs."

"Claude literally cannot skip the planning phase or write code before tests."Richard Joseph Porter

Then there's Simon Willison, whose endorsement carries weight precisely because it's measured. He calls creator Jesse Vincent "one of the most creative users of coding agents (Claude Code in particular)" he knows, and "way ahead of the curve." Willison highlights the engineering taste behind it: the core is "VERY token light," pulling in one doc under 2k tokens; Vincent uses subagents "to manage token-heavy stuff," keeps a "feelings journal," runs red/green TDD, and is "wildly experimenting" with Graphviz DOT graphs as workflow instructions.

The skeptics

Hacker News did not roll over. The criticism is worth taking seriously — it targets exactly the weak points an enthusiast tends to gloss over.

The thread on Vincent's announcement split sharply. On the positive side, redhale called sub-agents "an order-of-magnitude level feature" for longer loops, and danielbarla said Claude outperformed experienced teammates on dependency-injection debugging in legacy code. But the critics landed real hits.

"It could make Claude worse"

jackblemming raised the empirical gap directly: without evidence the ceremony actually helps, you're shipping vibes.

"without benchmarks or some kind of evaluation... this could make Claude worse."jackblemming, Hacker News

"Voodoo nonsense"

preommr dismissed the Cialdini-style persuasion framing — using influence principles to make the model comply — as unscientific theater dressed up as method.

"straight up voodoo nonsense."preommr, Hacker News (on the Cialdini framing)

It still misbehaved

troupo reported the familiar failure modes survived the framework: LLMs still duplicated existing functionality and ignored the codebase's established styles.

Where are the questions?

nightski criticized the agent's inability to ask clarifying questions — the very thing the brainstorming skill is meant to fix didn't always land.

The most useful skeptical voice may be Marc Nuri, whose analysis is balanced rather than dismissive. He frames Superpowers as "a directory of fourteen skills, each a single SKILL.md file" with a bootstrap hook under 2,000 tokens, portable across Claude Code, Cursor, and Copilot CLI. His diagnosis of why it works is sharp: the agent has capability but lacks discipline.

"Ask it to lecture you on TDD and it will. What it lacks is a mechanism that holds it to those concepts when shortcuts are easier."Marc Nuri — technical analysis of Superpowers

Nuri's example of that mechanism is the framework's "Iron Law": "NO PRODUCTION CODE WITHOUT A FAILING TEST FIRST." The TDD skill, he notes, "treats I'll write the test after as grounds to delete the implementation and start over." But he's clear-eyed about the limits: the multi-agent-coordination problem and the "agentic slop PR" problem (see below) remain unsolved at scale.

The overkill caveat

Even fans agree on one thing: the full ceremony is the wrong tool for a small job.

For "fast iterative design work like changing a button color," the multi-phase process slows you down. For small, contained fixes the plan-generation overhead can cost more tokens than just doing the thing. And reviewers point out a structural cost: skills "load fully into context on every invocation," so a single execution-layer skill can run 10K+ tokens. Discipline isn't free.

Complex, multi-file feature~14% token cut and a quality boost (per one benchmark-style writeup)

Trivial tweak (e.g. button color)The five-phase ceremony actively slows you down

The honest read. Superpowers pays off where context-loss and inconsistency hurt — big features, long sessions, unfamiliar codebases. On a one-line change, reach for stock Claude Code instead. The framework's own analysts say as much.

The 94% slop-PR story

The framework's most cautionary tale came from its own success. When tens of thousands of agents can be told "go fix this and open a PR," the inbox fills with lies.

Vincent audited the last 100 closed PRs on the Superpowers repo and found roughly 94% were AI-generated slop — agents that ignored the PR template, opened duplicates, fabricated problem descriptions, or pushed fork-specific changes upstream, usually because a human had casually told an agent to "go fix this and open a PR." He now closes such PRs within hours, sometimes with a blunt verdict.

"This pull request is slop that's made of lies."Jesse Vincent, closing an agentic PR

His response was to weaponize the framework against itself: a CLAUDE.md aimed directly at the contributing agents reading it.

"This repo has a 94% PR rejection rate. Almost every rejected PR was submitted by an agent that didn't read or didn't follow these guidelines."obra/superpowers — CLAUDE.md

That file codifies six mandatory pre-submission checks that every contributing agent must clear:

  1. Fill in every PR-template section

    Real answers, not placeholders.

  2. Search existing open AND closed PRs

    Don't re-submit what's already been rejected.

  3. Verify it's a real problem

    Confirm the bug actually exists before "fixing" it.

  4. Confirm the change belongs in core

    Fork-specific tweaks don't go upstream.

  5. Identify yourself

    Disclose model, harness, harness version, and every installed plugin.

  6. Show your human the complete diff

    Get explicit approval before submitting.

”

"Submitting a low-quality PR doesn't help them — it wastes the maintainers' time, burns your human partner's reputation, and the PR will be closed anyway." — obra/superpowers CLAUDE.md, addressing contributing agents

It's a striking inversion: a project built to give agents discipline had to write a separate rulebook to defend itself from agents. The slop-PR problem is, in Marc Nuri's words, one of the things agentic development hasn't yet solved at scale.

Stacking it with other tools

In practice, few people run Superpowers alone. It has a clear lane — execution — and developers pair it with complementary frameworks and tooling.

One widely-shared Dev.to writeup describes a three-framework stack with a memorable division of labor:

01
gstack
thinks · architectural vetting
→
02
GSD
stabilizes · context across sessions
→
03
Superpowers
executes · plan → TDD → verify
"gstack thinks, GSD stabilizes, Superpowers executes."imaginex — "A Claude Code Skills Stack" (Dev.to)

gstack handles decision-making and architectural vetting (/office-hours, /plan-ceo-review, /plan-eng-review); GSD keeps context stable across long sessions (PROJECT.md, DECISIONS.md, KNOWLEDGE.md); and Superpowers does the disciplined execution. The same author repeats the common criticism: "every task, no matter how small, runs through the full cycle."

A second pattern, from developer Chandler, goes wide instead of deep: Claude Code + Conductor + Superpowers running parallel git worktrees across multiple repos, fed Linear/GitHub issues plus NotebookLM research, with Context7 for docs and Tavily for web search. The motivation is eliminating "dead time" spent watching a single agent work.

"The planning part of Superpowers is definitely the reason it performs so much better."Chandler (chand1012) — "The best way to do agentic development in 2026" (Dev.to)

Ecosystem context

Superpowers doesn't exist in a vacuum — it sits on top of Anthropic's Agent Skills primitive and the Claude Code plugin system, and within a fast-growing catalog of community skills.

Anthropic formally introduced Agent Skills in an engineering post on October 16, 2025, defining a skill as a directory containing a SKILL.md file, loaded through progressive disclosure: just the name/description metadata at startup, the full body when relevant, and bundled files only as needed.

"Skills extend Claude's capabilities by packaging your expertise into composable resources for Claude, transforming general-purpose agents into specialized agents that fit your needs."Anthropic Engineering — "Equipping agents for the real world with Agent Skills"

On December 18, 2025, Anthropic republished Agent Skills as an open, cross-platform standard with a spec and SDK — which is exactly what lets Superpowers ship from one skill format to Claude Code, Codex, Gemini CLI, Cursor, OpenCode, Factory Droid, and GitHub Copilot CLI. The mental model Anthropic offers is friendly: "Building a skill for an agent is like putting together an onboarding guide for a new hire."

Plugins are the layer above skills. Per the Claude Code docs, "Plugins extend Claude Code with skills, agents, hooks, and MCP servers. Plugin marketplaces are catalogs that help you discover and install these extensions." A marketplace is just a git repo with a .claude-plugin/marketplace.json — added with /plugin marketplace add owner/repo and installed with /plugin install name@marketplace. Secondary commentary has aptly called the marketplace "npm for AI-assisted development workflows." Superpowers is distributed on both Anthropic's official marketplace and its own.

install superpowers
# From Anthropic's official marketplace
/plugin install superpowers@claude-plugins-official

# Or from the Superpowers marketplace
/plugin marketplace add obra/superpowers-marketplace
/plugin install superpowers@superpowers-marketplace

Around all of this, the community has built curated catalogs — the various awesome-claude-skills lists (travisvn, ComposioHQ's "1000+ production ready" collection, karanb192's "50+ verified") — which routinely cite Superpowers as a flagship methodology. Anthropic also publishes open-source skills at github.com/anthropics/skills.

Tutorials & walkthroughs

If you'd rather watch than read, the framework has spawned a small genre of video explainers — several framing it, only half-jokingly, as the end of "vibe coding."

The recurring theme across these tutorials is the same insight that drives the framework: Superpowers intercepts Claude at key moments — to ask questions first, enforce TDD, plan before coding, and self-review before moving on — rather than letting it improvise.

The bottom line

Strip away the divergent star counts and the hot takes, and the consensus is narrow but real: on substantial, multi-file work in unfamiliar code, the disciplined process measurably helps. On trivial changes, it's overkill. And at the scale of a popular open-source repo, agentic contribution is still a genuinely unsolved problem — a caution the project's own maintainer wrote down in plain Markdown, for the next agent to read.

The web's verdict, distilled: it doesn't make the model smarter — it makes the model finish the job properly, when the job is big enough to be worth it.
